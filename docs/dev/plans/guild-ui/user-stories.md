## ペルソナ

### ペルソナ1: プレイヤー

- **役割**: 「Atelier」をプレイするエンドユーザー（ターン制で庭・調合・ギルド納品を繰り返す錬金術師視点）
- **目的**: 自分が行った調合の成果（貢献度・報酬・指定依頼への合致）を把握し、次のターンの戦略（品質重視か特性重視か等）に反映させたい
- **技術レベル**: -（ゲームプレイヤーとしての技術レベルは本要件の対象外）

### ペルソナ2: 開発者（実装者）

- **役割**: 本plan（guild-ui）の実装・レビューを行うエンジニア
- **目的**: `GameState.deliver_pending_products()`の戻り値と納品前の調合物情報（スナップショット）を`display_results()`経由で正しく対応付け、誤表示やクラッシュのない実装を行いたい
- **技術レベル**: 上級（Godot/GDScript, Feature-Based Architecture, Functional Core/Imperative Shellに習熟）

## エピック1: 納品結果の確認

### US-001: 納品結果のリスト表示 🔵

**私は** プレイヤー **として**
**ターン終了時に納品された調合物の一覧（調合物名・品質・発現特性・貢献度・報酬）を確認したい**
**そうすることで** 自分の調合行動がギルドにどう評価されたかを把握できる

- **関連要件**: FR-001, FR-002, FR-003, FR-005, FR-008, FR-101
- **優先度**: Must Have
- **受入基準**: AC-001

### US-002: 合計値の確認 🔵

**私は** プレイヤー **として**
**複数の調合物を一度に納品した場合でも合計の貢献度と合計報酬を確認したい**
**そうすることで** ランクノルマ達成までの見通しを1回のターン終了操作単位で立てられる

- **関連要件**: FR-002, FR-004
- **優先度**: Must Have
- **受入基準**: AC-002

### US-003: 指定依頼合致の可視化 🔵

**私は** プレイヤー **として**
**各調合物が本日の指定依頼に合致したかどうかを一目で確認したい**
**そうすることで** 指定依頼を狙って調合した戦略の効果を実感でき、次ターンの戦略判断に活かせる

- **関連要件**: FR-201, FR-202
- **優先度**: Must Have
- **受入基準**: AC-003

- **優先度**: Should Have

## エピック3: 画面の導線（プレースホルダー）

### US-201: 結果確認後の次アクション導線 🟡

**私は** プレイヤー **として**
**納品結果を確認したら「閉じる/続ける」ボタンで先に進みたい**
**そうすることで** 結果画面に留まり続けることなく次の行動に移れる

- **関連要件**: FR-102, FR-402
- **優先度**: Must Have
- **受入基準**: AC-005

> 🔵 本ストーリーが指す「先に進む」の実処理（庭画面への遷移等）はMainScene側の統合作業（本plan外）が担う。本plan内では導線シグナルの発行までがスコープ（ヒアリング決定5）。

## エピック4: データ整合性（開発者向け）

### US-301: 納品結果と調合物情報の正しい対応付け 🔵

**私は** 開発者 **として**
**`AlchemyScreen`が渡す`ProductInstance`配列と`DeliveryResult`配列（`display_results()`の2引数）を正しくindex対応付けたい**
**そうすることで** 誤った調合物名や品質がプレイヤーに表示される事故を防げる

- **関連要件**: FR-007, FR-008, FR-101, CON-003, CON-004
- **優先度**: Must Have
- **受入基準**: AC-006, AC-009

> 🔵 2026-08-22の追加ヒアリングで「直接メソッド呼び出し方式」に確定した。`AlchemyScreen._on_end_turn_pressed()`が同一関数スコープ内でスナップショットと`deliver_pending_products()`の戻り値を取得し`GuildDeliveryScreen.display_results()`へ直接渡すため、`GameState.delivered`シグナル購読も`product_crafted`追跡も不要になり、index対応は構造的に保証される（詳細はrequirements.md CON-003参照）。

## エピック5: 空納品時の安全な表示

### US-401: 0件納品時に古い結果を誤表示しない 🔵

**私は** プレイヤー **として**
**納品する調合物が無いままターンを終了した場合に、直前の（無関係な）古い納品結果が画面に残り続けないようにしてほしい**
**そうすることで** 実際には起きていない納品が起きたかのように誤認することを防げる

- **関連要件**: FR-006
- **優先度**: Should Have
- **受入基準**: AC-008

> 🔵 2026-08-22の追加ヒアリングで解消。`GameStateGuildDelegate.deliver_pending_products()`は`_pending_products`が空の場合`delivered`シグナルを発行しないが（実装確認済み: `atelier/autoload/game_state_guild_delegate.gd` L18-19）、FR-006により`AlchemyScreen`は`delivered`シグナルの発行有無に関わらず`_on_end_turn_pressed()`のたびに必ず`display_results()`を呼び出す（`pending_products`が空だった場合は`display_results([], [])`）。このため`GuildDeliveryScreen`は毎回明示的に最新状態（0件を含む）へリセットされ、古い結果が残り続けることは構造的に発生しない。
