# title-settings-screens 要件定義書

## 概要

本Planは、これまで「未実装・設計スコープ外」と明記されてきたタイトル画面・設定画面の2画面を新規に追加する。現在の起動フローは `BootScene → SlotSelectScreen（新規/つづき統合選択）→ MainScene` であり、本Planはこの手前に `TitleScreen`（新規Feature `features/title/`）を追加し、「はじめる」「せってい」の2項目メニューを提供する。「せってい」からは新規Feature `features/settings/` の設定パネル（`settings_panel.tscn`）をオーバーレイ表示する。この設定パネルはゲームプレイ中にも `RankHud` の歯車アイコンから共通コンポーネントとして呼び出せる。設定値（BGM/SE音量・ウィンドウモード・演出簡略化フラグ）は新規Autoload `SettingsService` が `user://settings.json`（全セーブスロット共通のグローバル設定ファイル）として管理し、`GameState`・`SaveService`には一切影響を与えない独立した仕組みとする。

## 用語集

| 用語 | 定義 |
|-----|------|
| TitleScreen | 新規Feature `features/title/`のUIシーン。ゲーム起動後最初に表示され、「はじめる」「せってい」の2項目メニューを持つ |
| SlotSelectScreen | PR#45実装済みの3固定スロット選択画面（`features/save_load/ui/slot_select_screen.tscn`）。新規/つづきの分岐を担う |
| 設定パネル (SettingsPanel) | 新規Feature `features/settings/`のUIシーン（`settings_panel.tscn`）。TitleScreenとRankHudの両方から`add_child()`でオーバーレイ表示される共通コンポーネント |
| SettingsService | 新規Autoload。`user://settings.json`の読み書き、`AudioServer`バス音量・`DisplayServer`ウィンドウモードへの即時反映、演出簡略化フラグの保持を担う |
| SettingsData | 設定値の型（BGM音量・SE音量・ウィンドウモード・演出簡略化フラグ）を保持するランタイム状態型（`state/settings_data.gd`） |
| SettingsCodec | 設定データのJSON化・パース・型検証を行う純粋関数群（`logic/settings_codec.gd`）。チェックサムは持たない |
| 演出簡略化フラグ | Tween等の演出を簡略化するための設定値。本Planでは値の保持・取得APIのみ提供し、既存画面への適用は行わない |
| RankHud | 全フェーズ共通の常時表示ヘッダー（`shared/ui/rank_hud.gd`）。本Planで歯車アイコンボタンを追加する |

## 機能要件（EARS記法）

### 普遍要件（SHALL）

- **FR-001**: `BootScene`は、マスターデータ検証成功後の遷移先を`res://features/title/ui/title_screen.tscn`としなければならない 🔵 *[ヒアリング: BootSceneの遷移先変更]*
  - 関連: US-001, AC-001
- **FR-002**: `TitleScreen`は、メニュー項目として「はじめる」「せってい」の2項目のみを表示しなければならない 🔵 *[ヒアリング: シンプル2項目]*
  - 関連: US-002, AC-002
- **FR-003**: `SettingsService`は、設定データを`user://settings.json`へ永続化しなければならない 🔵 *[ヒアリング: グローバル設定ファイル]*
  - 関連: US-105, AC-009
- **FR-004**: `SettingsService`は、BGM音量・SE音量・ウィンドウモード・演出簡略化フラグそれぞれの取得APIを提供しなければならない 🔵 *[ヒアリング: 4つの設定値]*
  - 関連: US-102, US-103, US-104, AC-012
- **FR-005**: `SettingsService`は、`user://settings.json`が存在しない場合、BGM音量100%・SE音量100%・ウィンドウモード（ウィンドウ表示）・演出簡略化OFFのデフォルト値を用いなければならない 🔵 *[ヒアリング: デフォルト値]*
  - 関連: US-301, AC-010
- **FR-006**: 設定パネル（`settings_panel.tscn`）は、`TitleScreen`と`RankHud`の両方から共通コンポーネントとしてインスタンス化可能な独立シーンとして実装しなければならない 🔵 *[ヒアリング: 共通コンポーネント]*
  - 関連: US-101, US-201, AC-004, AC-005
- **FR-007**: `RankHud`は、すべてのフェーズ画面において歯車アイコンボタンを表示しなければならない 🔵 *[ヒアリング: RankHudへの歯車アイコン追加]*
  - 関連: US-201, AC-005
- **FR-008**: `SettingsCodec`は、`user://settings.json`から読み込んだ生データの型を検証し、不正な場合はデフォルト値へフォールバックする判定結果を返さなければならない 🔵 *[ヒアリング: security.mdの`_is_valid_save_data()`パターンに準拠]*
  - 関連: US-301, AC-010

- **FR-101**: ユーザーが`TitleScreen`で「はじめる」を押下した場合、システムは`res://features/save_load/ui/slot_select_screen.tscn`へ`change_scene_to_file`しなければならない 🔵 *[ヒアリング: はじめる押下時の遷移]*
  - 関連: US-001, AC-003
- **FR-102**: ユーザーが`TitleScreen`で「せってい」を押下した場合、システムは`settings_panel.tscn`のインスタンスを`add_child()`でオーバーレイ表示しなければならない 🔵 *[ヒアリング: せってい押下時のオーバーレイ表示]*
  - 関連: US-101, AC-004
- **FR-103**: ユーザーが`RankHud`の歯車アイコンを押下した場合、システムは`settings_panel.tscn`のインスタンスを`add_child()`でオーバーレイ表示しなければならない 🔵 *[ヒアリング: ゲーム中からの設定アクセス]*
  - 関連: US-201, AC-005
- **FR-104**: ユーザーが設定パネルでBGM音量を変更した場合、システムは変更直後に対応する`AudioServer`バスの音量へ即時反映しなければならない 🔵 *[ヒアリング: 即時反映]*
  - 関連: US-102, AC-006
- **FR-105**: ユーザーが設定パネルでSE音量を変更した場合、システムは変更直後に対応する`AudioServer`バスの音量へ即時反映しなければならない 🔵 *[ヒアリング: 即時反映]*
  - 関連: US-102, AC-006
- **FR-106**: ユーザーが設定パネルでウィンドウモードを切り替えた場合、システムは変更直後に`DisplayServer.window_set_mode()`へ即時反映しなければならない 🔵 *[ヒアリング: 画面モード設定]*
  - 関連: US-103, AC-007
- **FR-107**: ユーザーが設定パネルを閉じた場合、システムは現在の設定値を`user://settings.json`へ書き込まなければならない 🔵 *[ヒアリング: 閉じるタイミングで保存]*
  - 関連: US-105, AC-009
- **FR-108**: ユーザーが設定パネルを閉じた場合、システムは設定パネルのノードを`queue_free()`で解放しなければならない 🔵 *[ヒアリング: 閉じるボタンでqueue_free()]*
  - 関連: US-105, AC-009

### 状態駆動要件（WHERE）

- **FR-201**: 設定パネルがオーバーレイ表示されている間、システムは背後の`TitleScreen`または現在のフェーズ画面の表示状態を変更してはならない（そのまま裏に残す） 🔵 *[ヒアリング: パネルを閉じれば元の画面に戻るだけの構造]*
  - 関連: US-202, AC-011
- **FR-202**: 設定パネルがオーバーレイ表示されている間、`RankHud`は`GameState`のsignalに引き続き追随して自身の表示（ランク名・ノルマ・残ターン・ゴールド）を更新してもよい 🟡 *[推測: RankHudの既存自己完結設計を変更する理由がないため]*
  - 関連: US-202, AC-011

### 任意要件（MAY）

- **FR-301**: `TitleScreen`は、メニューの上部に静的なタイトルロゴ/テキスト領域を表示してもよい 🟡 *[推測: ヒアリングに明記なし。一般的なタイトル画面の構成要素]*
  - 関連: US-401, AC-002
- **FR-302**: `SettingsService`は、演出簡略化フラグの値を将来の演出実装Planから参照可能なAPIとして提供してもよい（本Planでは既存画面への適用は行わない） 🔵 *[ヒアリング: 将来の土台のみ用意]*
  - 関連: US-104, AC-008
- **FR-303**: 設定パネルは、表示中にEscapeキーで閉じられなければならない（一般的なモーダルパネルのUX慣習に合わせる） 🔵 *[ヒアリング: 2026-09-03確認。閉じるボタンに加えEscapeキー対応を追加確定]*
  - 関連: US-105, AC-013

### 禁止要件（MUST NOT）

- **FR-401**: `TitleScreen`および設定パネルの表示・非表示切替は、フェード等の画面遷移アニメーションを実装してはならない（即時切替とする） 🔵 *[ヒアリング: 画面遷移アニメーションは実装しない]*
  - 関連: US-002, AC-014
- **FR-402**: 設定パネルは、`GameState.set_phase()`を呼び出してはならない 🔵 *[ヒアリング: GameState・SaveServiceに一切影響を与えない]*
  - 関連: US-202, AC-011
- **FR-403**: 設定パネルは、`SaveService.autosave()`をトリガーしてはならない 🔵 *[ヒアリング: オートセーブをトリガーしない]*
  - 関連: US-202, AC-011
- **FR-404**: `SettingsService`は、設定データにチェックサムによる改ざん検出機構を実装してはならない 🔵 *[ヒアリング: 改ざん検出用チェックサムは設定データには不要]*
  - 関連: US-301, AC-010
- **FR-405**: `TitleScreen`は、「はじめる」押下時に新規/つづきの分岐処理を自ら行ってはならない（この分岐は引き続き`SlotSelectScreen`が担う） 🔵 *[ヒアリング: TitleScreen側で分岐しない]*
  - 関連: US-001, AC-003
- **FR-406**: `TitleScreen`は、ゲーム終了（アプリケーション終了）ボタンを設けてはならない 🔵 *[ヒアリング: ゲーム終了ボタンは設けない。OS標準のウィンドウクローズに委ねる]*
  - 関連: US-002, AC-002
- **FR-407**: 設定パネルが既に開いている状態で「せってい」ボタンまたは歯車アイコンが再度押下された場合、システムは複数の設定パネルインスタンスを同時に生成してはならない（既存インスタンスが存在する場合は押下自体を無視する） 🔵 *[ヒアリング: 2026-09-03確認。多重起動防止ガードを追加確定]*
  - 関連: US-201, AC-013

## 非機能要件

### パフォーマンス

- **NFR-001**: 音量・ウィンドウモードの変更操作は、体感遅延なく（同一フレーム〜数フレーム以内に）反映されなければならない 🟡 *[妥当推測: 即時反映という要件からの性能目標の具体化]*
- **NFR-002**: `TitleScreen`・設定パネルは、`_process()`による毎フレーム処理を持たず、イベント駆動（`signal`/ボタンの`pressed`）で状態更新を行わなければならない 🟡 *[妥当推測: performance.mdの一般原則をこのPlanに適用]*

### セキュリティ

- **NFR-101**: `SettingsCodec`は、`user://settings.json`のJSONパース失敗、またはトップレベルキーの型不一致を検出し、いずれの場合もデフォルト値へフォールバックしなければならない 🔵 *[ヒアリング: security.mdの`_is_valid_save_data()`パターンに準拠]*
- **NFR-102**: `SettingsService`は、設定ファイルの内容を動的コード評価（`Expression.execute()`等）に用いてはならない 🔵 *[security.md: 未検証の動的コード評価の禁止を踏襲]*

### ユーザビリティ

- **NFR-201**: `TitleScreen`・設定パネルのテキストはすべて日本語で表示し、既存の`main_theme.tres`（日本語フォント）を流用しなければならない 🔵 *[ヒアリング: 日本語UI前提]*
- **NFR-202**: `TitleScreen`・設定パネルの新規UI要素（ボタン・パネル・スライダー等）は、色・角丸・余白を`UiTheme`定数経由で指定しなければならず、ハードコードしてはならない 🔵 *[design-guide.md準拠]*
- **NFR-203**: `RankHud`の歯車アイコンボタンは、通常フェーズおよび昇格試験中を含むすべてのフェーズ画面で押下可能でなければならない 🟡 *[妥当推測: RankHudが「全フェーズ共通」ヘッダーであるため、追加ボタンも同様の可視性を持つべき]*

### 信頼性

- **NFR-301**: `DisplayServer.window_set_mode()`が実行環境でサポートされないモードを指定された場合、システムは`push_warning()`でログ出力するのみとし、UI上へのエラー表示・追加のフォールバック処理は行わない（`window_set_mode()`自体は成否を返さないAPIのため、`window_get_mode()`による事後検証で警告要否のみ判断する） 🔵 *[ヒアリング: 2026-09-03確認。何もしない（push_warningのみ）と確定]*

## 制約

- **CON-001**: 新規Feature（`features/title/`, `features/settings/`）は、`architecture.md`のFeature-Based Architectureに従い`logic/`（必要な場合のみ）・`state/`・`ui/`のディレクトリ構成としなければならない 🔵 *[ヒアリング: 既存Featureと同じ構成]*
- **CON-002**: 新規Autoload `SettingsService`を追加する場合、`atelier/project.godot`の`[autoload]`セクションへ`SaveService`と同じパターンで登録しなければならない 🔵 *[ヒアリング: project.godotへの登録が必要]*
- **CON-003**: 設定の永続化は3固定セーブスロット（`SaveService`管理）とは独立したグローバルファイル（`user://settings.json`）としなければならない 🔵 *[ヒアリング: 全スロット共通・セーブスロットとは独立]*
- **CON-004**: 本Planの音量制御スコープは`AudioServer`バス音量の制御までとし、BGM/SE音源の再生システム自体の実装は行わない（現状プロジェクトに音源再生システムが一切存在しないため） 🔵 *[ヒアリング: 音源自体の実装は本Planのスコープ外]*
- **CON-005**: 演出簡略化フラグは値の保持・取得APIを提供するのみとし、既存画面（Tween等）への適用作業は本Planのスコープ外とする 🔵 *[ヒアリング: 将来Planが参照する前提の土台のみ]*
- **CON-006**: UIは`Control`継承の標準Godotノードで構成し、外部UIプラグインを使用してはならない 🔵 *[godot-best-practices.md準拠]*
- **CON-007**: テストは既存の`.claude/rules/testing.md`の規約に従いGdUnit4で実装し、`SettingsService`（Autoload）を`monitor_signals()`する場合は`monitor_signals(obj, false)`を明示しなければならない 🔵 *[ヒアリング: Autoloadのテストの罠に注意]*
