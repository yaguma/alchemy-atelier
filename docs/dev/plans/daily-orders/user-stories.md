## ペルソナ

本プロジェクトは個人開発のシングルプレイ・オフラインゲームであり、外部ユーザー種別は1種類のみ。

### ペルソナ1: プレイヤー

- **役割**: 錬金術師としてギルドのランクノルマを達成していくシングルプレイヤー
- **目的**: 庭で素材を仕込み、調合で「品質を盛るか特性を宿すか」を判断し、ギルド納品で貢献度と報酬を得てランクを上げる
- **技術レベル**: 初級〜中級（ゲーム内の表示のみで判断でき、ソースコードやデバッグコンソールを参照しない）
- **本Planでの関心事**: 「今このターンは何を作ると得なのか」を、調合の素材投入を決める**前に**知りたい

> 補足: 開発者（本リポジトリの保守者）は本Planではペルソナとして扱わず、保守性に関する要求は
> requirements.md の NFR-101〜NFR-103 / CON-001〜CON-012 として整理している。

## エピック1: 指定依頼が実データとして存在し、ゲーム開始時から機能する

### US-001: ゲーム開始直後から指定依頼が提示される 🔵

**私は** プレイヤー **として**
**ゲームを起動して最初のターンを迎えた時点で、その日の指定依頼が決まっている状態にしたい**
**そうすることで** 初回ターンの調合から「指定に合わせるか否か」という判断を働かせられる

- **関連要件**: FR-001, FR-002, FR-003, FR-008, FR-101
- **優先度**: Must Have
- **受入基準**: AC-001, AC-004

---

## エピック2: 指定依頼が達成可能な範囲で毎ターン切り替わる

### US-002: 毎ターン指定依頼が入れ替わる 🔵

**私は** プレイヤー **として**
**ターンが終わるたびに指定依頼が新しく抽選されるようにしたい**
**そうすることで** 毎ターン異なる目標が生まれ、庭の仕込みと調合の判断が単調にならない

- **関連要件**: FR-004, FR-005, FR-006, FR-102, FR-301, FR-303, FR-404
- **優先度**: Must Have
- **受入基準**: AC-002, AC-005

### US-003: 達成しようのない指定依頼が出てこない 🔵

**私は** プレイヤー **として**
**まだ解禁していないレシピや、特性が未解禁のランクでの特性指定を、指定依頼として提示されたくない**
**そうすることで** 「どうやっても達成できない依頼」を見せられて無力感を覚えることがない

- **関連要件**: FR-005, FR-103, FR-203, FR-405
- **優先度**: Must Have
- **受入基準**: AC-002, AC-003

### US-004: 指定依頼がない日でも普通に納品できる 🔵

**私は** プレイヤー **として**
**達成可能な指定依頼が1件もないターンでも、通常通り調合物を納品して貢献度と報酬を得たい**
**そうすることで** ゲームの進行が止まったりエラー表示に遭遇したりしない

- **関連要件**: FR-103, FR-202, FR-405
- **優先度**: Must Have
- **受入基準**: AC-003, AC-009

## エピック3: 現在の指定依頼をプレイヤーが確認できる

### US-005: 調合を決める前に指定依頼の内容が分かる 🔵

**私は** プレイヤー **として**
**素材を投入枠に入れる前に、今の指定依頼が「どのレシピ」または「どの特性」を求めているかを画面で確認したい**
**そうすることで** 「品質を盛るか特性を宿すか」の判断材料として指定依頼を組み込める

- **関連要件**: FR-007, FR-104, NFR-201
- **優先度**: Must Have
- **受入基準**: AC-006

### US-006: 指定依頼に合致した時の得の大きさが分かる 🟡

**私は** プレイヤー **として**
**指定依頼に合致させた場合のボーナス倍率を確認したい**
**そうすることで** 「指定に寄せるコスト」と「得られるボーナス」を天秤にかけて判断できる

- **関連要件**: FR-007, FR-407, NFR-102
- **優先度**: Should Have
- **受入基準**: AC-006

### US-007: 指定依頼がないターンだと明示的に分かる 🟡

**私は** プレイヤー **として**
**指定依頼がないターンには、画面が空欄になるのではなく「指定依頼なし」と読み取れる表示をしてほしい**
**そうすることで** バグで表示が消えているのか、そもそも依頼がないのかを取り違えない

- **関連要件**: FR-103, FR-202, NFR-202
- **優先度**: Should Have
- **受入基準**: AC-006, AC-003

### US-008: 現在の投入内容が指定に合致しているか一目で分かる 🟡

**私は** プレイヤー **として**
**投入枠に素材を入れた時点で、その調合物が指定依頼に合致する見込みかを確認したい**
**そうすることで** 納品して初めてボーナスの有無を知る、という後出しを避けられる

- **関連要件**: FR-304
- **優先度**: Could Have（`alchemy_screen.gd` の `result.order_matched` が既にプレビューへ渡っており、既存機構で実現可能）
- **受入基準**: AC-006

## エピック4: 昇格試験中は指定依頼が働かない（既存契約の維持）

### US-009: 昇格試験中はボーナスなしの実力勝負になる 🔵

**私は** プレイヤー **として**
**昇格試験中は指定依頼のボーナスが働かず、プレビューにもボーナスが乗らない状態にしてほしい**
**そうすることで** 試験の難易度が指定依頼の運に左右されず、プレビューと実際の納品結果も食い違わない

- **関連要件**: FR-201, FR-302, FR-402
- **優先度**: Must Have（既存契約の**維持**が要求。新規実装ではない）
- **受入基準**: AC-008

## ユーザージャーニー

### ジャーニー1: 通常ターンのループ（本Planの主要フロー）

```
ゲーム起動          →  庭で仕込む   →  調合画面で指定依頼を確認  →  投入内容を決める  →  納品   →  ターン終了・再抽選
（初回抽選）                            （倍率と対象を見る）        （合致 or 品質重視）  （ボーナス適用）
  US-001                                     US-005 / US-006          US-008            US-004      US-002
```

### ジャーニー2: 序盤（Gランク・レシピ1種のみ）の絞り込み

```
Gランク開始  →  特性未解禁 & 解禁レシピ1件  →  抽選プールが item 1件のみ  →  そのレシピが指定される
                     （trait は除外）                                          or プール空なら「指定依頼なし」
     US-001                US-003                      US-003                        US-004 / US-007
```

### ジャーニー3: 昇格試験

```
ノルマ達成  →  昇格試験開始（in_exam=true）  →  指定依頼の表示・ボーナスともに無効  →  試験終了
                                                          US-009
```
