## ペルソナ

### ペルソナ1: 錬金術師見習い（プレイヤー）

- **役割**: ギルドランク制デッキ構築RPG「Atelier」のプレイヤー。庭で仕込んだ素材を調合台へ投入し、品質を盛るか特性を宿すかのトレードオフをしながら調合物を作る
- **目的**: 投入枠（4枠、恒久投資で+1）に何を入れるかを毎ターン悩みながら選び、貢献度（ランクノルマ削り）と報酬（ゴールド）のどちらを優先するか判断したい
- **技術レベル**: ゲームプレイヤーとしては初級〜中級。本plan自体はUI非対象（別task）のため、本ペルソナの体験はAlchemyScreen実装後に実現される前提の要件として記述する

### ペルソナ2: 実装者（後続UI・GuildSystem開発者）

- **役割**: 本plan完了後に`AlchemyScreen`（UI plan）・`GuildSystem`（guild plan）を実装するエンジニア
- **目的**: `GameState.execute_alchemy`の入出力契約（引数・`Result`・シグナル・`pending_products`）が明確で、UIやギルド納品ロジックから安心して呼び出せる状態にしたい
- **技術レベル**: 上級（本プロジェクトのアーキテクチャ規約を理解している）

## エピック1: 品質計算（投入から品質確定まで）

### US-001: 投入素材の平均品質で調合物の品質を決めたい 🔵

**私は** 錬金術師見習い **として**
**投入枠に入れた素材の品質スコアの平均で調合物の品質が決まってほしい**
**そうすることで** 高品質素材を集めて投入すれば狙い通り高品質な調合物が作れると理解しながら投入計画を立てられる

- **関連要件**: FR-004, FR-005, FR-105
- **優先度**: Must Have
- **受入基準**: AC-001

### US-002: 触媒を1つ混ぜて品質を底上げしたい 🔵

**私は** 錬金術師見習い **として**
**投入枠に触媒（`trait_tags`に`catalyst`を持つ素材）を1つ入れることで、平均品質+1のボーナスを得たい**
**そうすることで** 平均だけでは届かない品質帯（特にS品質）を触媒購入という追加投資で狙えるようになる

- **関連要件**: FR-005, FR-106, FR-202
- **優先度**: Must Have
- **受入基準**: AC-002, AC-011

## エピック2: 特性発現と価値算出

### US-003: 同じ特性を2個以上まとめて投入して特性を発現させたい 🔵

**私は** 錬金術師見習い **として**
**同一の特性タグを持つ素材を2個以上投入することで、その特性を確実に発現させたい**
**そうすることで** 「1個だけ紛れ込んだ特性は無駄になる」というルールを理解した上で、狙った特性を確実に発現させる投入計画を立てられる

- **関連要件**: FR-005, FR-107, FR-201
- **優先度**: Must Have
- **受入基準**: AC-003, AC-011

### US-004: 貢献度系・報酬系の特性を狙って組み合わせ価値を伸ばしたい 🔵

**私は** 錬金術師見習い **として**
**発現した貢献度系特性（聖・浄・癒）は貢献度に、報酬系特性（金・華・稀）は報酬にだけボーナスが乗ってほしい**
**そうすることで** 「ノルマを早く削りたいので貢献度系に寄せる」「ゴールドを稼ぎたいので報酬系に寄せる」という明確な戦略選択ができる

- **関連要件**: FR-005, FR-108, FR-109, FR-406
- **優先度**: Should Have
- **受入基準**: AC-004

### US-005: 解禁済みレシピを選んで基礎価値を決めたい 🔵

**私は** 錬金術師見習い **として**
**調合実行前に解禁済みレシピから1つを選び、そのレシピの基礎貢献度・基礎報酬を価値計算の土台にしたい**
**そうすることで** レシピごとの得意分野（貢献度寄り/報酬寄り）を理解して使い分けられる

- **関連要件**: FR-001, FR-002, FR-007, FR-101, FR-102, FR-110, FR-111, FR-301
- **優先度**: Must Have
- **受入基準**: AC-009, AC-010, AC-014

## エピック3: 調合実行の正当性検証

### US-006: 持っていない素材や重複投入では調合が実行されないようにしたい 🔵

**私は** 錬金術師見習い **として**
**在庫にない素材IDや、同じ素材を2回投入するような不正な指定では調合が実行されず失敗してほしい**
**そうすることで** UI側のバグや不整合があっても在庫が壊れず、安心して調合操作ができる

- **関連要件**: FR-102, FR-113
- **優先度**: Must Have
- **受入基準**: AC-005, AC-006, AC-015

### US-007: 投入枠数を超える・0個投入では調合を実行できないようにしたい 🔵

**私は** 錬金術師見習い **として**
**投入枠の上限を超えて素材を入れたり、何も入れずに調合を実行しようとした場合は失敗してほしい**
**そうすることで** 「最低1個・上限枠数以下」というルールを安心して前提にできる

- **関連要件**: FR-001, FR-006, FR-101, FR-103
- **優先度**: Must Have
- **受入基準**: AC-007, AC-008

### US-012: Gランクでは特性が一切効かないことを保証したい 🔵

**私は** 錬金術師見習い **として**
**特性システムが未解禁のランク（Gランク想定）では、触媒ボーナスも特性発現も一切効かず、純粋な品質平均だけで勝負したい**
**そうすることで** 「Gランク・1ターン目は特性封印」というゲームの難易度カーブ（序盤は基礎だけで戦う）を体験できる

- **関連要件**: FR-104, FR-201, FR-202
- **優先度**: Must Have
- **受入基準**: AC-011

## エピック4: 未納品キューとの連携（後続機能への橋渡し）

### US-008: 調合成功で素材が消費され調合物が積まれてほしい 🔴

**私は** 錬金術師見習い **として**
**調合が成功したら、投入した素材が在庫から消え、完成した調合物が納品待ちとして貯まってほしい**
**そうすることで** （後続のguild plan実装後に）調合したものが自動でギルドに納品される流れを体験できる

- **関連要件**: FR-008, FR-112
- **優先度**: Must Have
- **受入基準**: AC-010

### US-009: get_state()の戻り値を書き換えても内部状態が壊れないようにしたい 🔵

**私は** 実装者 **として**
**`GameState.get_state()`が返す`pending_products`・`inventory`を呼び出し元が変更しても、`GameState`内部の正本データが汚染されないでほしい**
**そうすることで** UI側の実装ミスがゲーム状態の整合性を壊すリスクを構造的に排除できる

- **関連要件**: FR-403
- **優先度**: Should Have
- **受入基準**: AC-012

### US-010: 調合失敗時にerror_code付きで理由を受け取りたい 🔴

**私は** 実装者 **として**
**調合実行が失敗した場合、失敗理由を表す`error_code`とともにシグナルを受け取りたい**
**そうすることで** 将来のUI実装でトースト等に理由別のメッセージを出し分けられる

- **関連要件**: FR-113
- **優先度**: Should Have
- **受入基準**: AC-015

### US-011: pending_productsを後続のguild planが安心して消費できる契約にしたい 🔵

**私は** 実装者 **として**
**`pending_products`が「調合成功時に追加されるだけの単純なキュー」として設計されていてほしい（本plan内ではギルド納品ロジックを含まない）**
**そうすることで** guild plan側は`pending_products`を消費する処理だけに集中して実装できる

- **関連要件**: FR-008, CON-004
- **優先度**: Should Have
- **受入基準**: AC-010
