## ペルソナ

### ペルソナ1: 開発者兼プレイテスター（本プロジェクトの唯一のユーザー）

- **役割**: 個人開発者。設計・実装・プレイテストをすべて1人で担う
- **目的**: 各機能Planで個別に完成させた5画面を実際に繋ぎ、「調合で一瞬迷うか」というゲームの核心仮説を実機の通しプレイで検証したい
- **技術レベル**: 上級（Godot / GDScript / GdUnit4 に習熟。コードとテストの両方を自身で読み書きする）
- **現在の痛み**: `main.tscn` が空の `Control` 1個であるため、ゲームを起動しても何も表示されない。各画面は GdUnit4 テストでしか動作確認できず、遊びとしての手触りが一度も確認できていない

### ペルソナ2: 将来のプレイヤー（本Planでは間接的な受益者）

- **役割**: ゲームを最初から最後まで遊ぶ人
- **目的**: 庭で仕込み、調合で迷い、ギルドに納品し、ランクを上げてクリアするという一連の体験を途切れなく味わいたい
- **技術レベル**: 初級（Godot の内部構造を一切知らない）

## エピック1: フェーズ移動の骨格

ゲームの器としての MainScene を成立させ、4画面を行き来できるようにする。

### US-001: 庭と調合をタブで自由に行き来する 🔵

**私は** プレイヤー **として**
**画面上部のタブで庭画面と調合画面を自由に切り替えたい**
**そうすることで** 「何を仕込むか」と「何を作るか」を往復しながら考えられる

- **関連要件**: FR-001, FR-003, FR-004, FR-101, FR-102, FR-103
- **優先度**: Must Have
- **受入基準**: AC-001, AC-003, AC-004

### US-002: 常にランク状況とゴールドを把握する 🔵

**私は** プレイヤー **として**
**どの画面にいてもランク名・ノルマ残量・残ターン・所持ゴールドを見たい**
**そうすることで** 「あと何ターンでいくら稼がなければならないか」を判断材料にできる

- **関連要件**: FR-002, FR-114, FR-302, NFR-202
- **優先度**: Must Have
- **受入基準**: AC-002, AC-016

### US-003: どの画面からでも工房へ寄り道して戻る 🔵

**私は** プレイヤー **として**
**庭からも調合からもショップアイコンで工房強化画面へ行き、閉じたら元の画面に戻りたい**
**そうすることで** ターン中いつでも消耗投資の判断ができ、作業の流れが途切れない

- **関連要件**: FR-104, FR-105
- **優先度**: Must Have
- **受入基準**: AC-007

### US-004: フェーズ切替が唐突に感じられない 🟡

**私は** プレイヤー **として**
**画面が切り替わるときに軽い演出があってほしい**
**そうすることで** 状況が変わったことを認識しやすい

- **関連要件**: FR-301
- **優先度**: Could Have
- **受入基準**: AC-016

### US-005: 画面破棄時に購読が漏れない 🔵

**私は** 開発者 **として**
**MainScene が GameState への signal 購読を確実に解除してほしい**
**そうすることで** テストの連続実行や将来のシーン再構築でメモリリーク・二重発火が起きない

- **関連要件**: FR-005
- **優先度**: Must Have
- **受入基準**: AC-005

### US-006: 起動しただけで実データが載った状態になる 🔵

**私は** 開発者 **として**
**MainScene の起動時にマスターデータが自動でロードされてほしい**
**そうすることで** テスト用のセットアップコードを書かなくても実機で種・レシピ・強化項目が並ぶ

- **関連要件**: FR-006
- **優先度**: Must Have
- **受入基準**: AC-006
- **備考**: 呼び出し主体は MainScene に確定（2ラウンド目AskUserQuestionで「含める」を選択）。BootScene は変更しない

## エピック2: ターンループの成立

調合 → ギルド納品 → 庭へ戻る、という1ターンの周回を成立させる。

### US-101: 納品結果が出るときだけ結果画面が出る 🔵

**私は** プレイヤー **として**
**納品結果を確認すべきときだけギルド納品の結果表示が現れてほしい**
**そうすることで** 何も納品していないのに空の結果パネルが調合画面に居座って邪魔をしない

- **関連要件**: FR-203
- **優先度**: Must Have
- **受入基準**: AC-015

### US-102: 納品結果を確認して庭へ戻る 🔵

**私は** プレイヤー **として**
**ギルド納品の結果を確認して「続ける」を押したら庭画面へ戻りたい**
**そうすることで** 次のターンの仕込みへ自然に進める

- **関連要件**: FR-106, FR-107, FR-402
- **優先度**: Must Have
- **受入基準**: AC-008

### US-103: ターンを終えるとランク判定が確定する 🔵

**私は** プレイヤー **として**
**ターンを終えたときにランクノルマの達成状況が判定されてほしい**
**そうすることで** 昇格試験が始まったり降格したりという進行が実際に起きる

- **関連要件**: FR-115
- **優先度**: Must Have
- **受入基準**: AC-013
- **備考**: `commit_rank_outcome()` の呼び出しをスコープに含めることが確定（2ラウンド目AskUserQuestion）。呼び出し箇所（AlchemyScreen経由かMainScene経由か）はPhase 2設計で確定する

## エピック3: 昇格試験と終局

一発勝負の昇格試験と、その先のクリア/ゲームオーバーへ正しく分岐させる。

### US-201: 昇格試験が始まったら試験画面に集中する 🟡

**私は** プレイヤー **として**
**昇格試験が始まったら調合画面（試験モード）に切り替わり、庭へは戻れなくなってほしい**
**そうすることで** 一発勝負の局面であることが操作可能な範囲から伝わる

- **関連要件**: FR-108, FR-116, FR-201
- **優先度**: Must Have
- **受入基準**: AC-009, AC-013, AC-014

### US-202: 試験に合格したら工房強化へ進む 🔵

**私は** プレイヤー **として**
**昇格試験に合格したら工房強化画面が自動で開いてほしい**
**そうすることで** 昇格の報酬である恒久投資をすぐに検討できる

- **関連要件**: FR-109, FR-116
- **優先度**: Must Have
- **受入基準**: AC-010, AC-013

### US-203: 試験に落ちても庭から再挑戦できる 🔵

**私は** プレイヤー **として**
**昇格試験に不合格でも庭画面に戻って立て直したい**
**そうすることで** 一度の失敗でゲームが終わらず再挑戦できる

- **関連要件**: FR-110
- **優先度**: Must Have
- **受入基準**: AC-010

### US-204: 最終ランクを突破したらクリア画面を見る 🔵

**私は** プレイヤー **として**
**最終ランクの昇格試験に成功したらゲームクリア画面が表示されてほしい**
**そうすることで** 到達した達成を明確に受け取れる

- **関連要件**: FR-111, FR-113, FR-202, FR-403
- **優先度**: Must Have
- **受入基準**: AC-011, AC-012, AC-014

### US-205: 連続降格でゲームオーバー画面を見る 🔵

**私は** プレイヤー **として**
**規定回数連続で降格したらゲームオーバー画面が表示されてほしい**
**そうすることで** 失敗が明確な終わりとして提示される

- **関連要件**: FR-112, FR-113, FR-202, FR-403
- **優先度**: Must Have
- **受入基準**: AC-011, AC-012, AC-014

## エピック4: 通しプレイの自動検証

手で遊んで確かめた流れを、壊れないコードとして残す。

### US-301: 5画面横断の通しプレイを自動テストで守る 🔵

**私は** 開発者 **として**
**庭→調合→納品→庭→試験→合否分岐までを1本の GdUnit4 統合テストで検証したい**
**そうすることで** 今後どの機能Planを触っても、通しプレイの導線が壊れたことに即座に気付ける

- **関連要件**: NFR-301, NFR-302, NFR-001
- **優先度**: Must Have
- **受入基準**: AC-018（横断的受入基準）

### US-302: アーキテクチャ規約からの逸脱が持ち込まれない 🔵

**私は** 開発者 **として**
**MainScene が GameState 以外の経路で他Feature の内部状態を触っていないことを保証したい**
**そうすることで** Feature 間の依存が増えず、機能単位の削除・差し替えの容易性が保たれる

- **関連要件**: FR-401, FR-402, FR-404, FR-406
- **優先度**: Must Have
- **受入基準**: AC-017

## ユーザージャーニー

### ジャーニー1: 通常ターンの1周（ハッピーパス）

```
起動(main.tscn表示)  →  庭で植付/収穫  →  タブで調合へ  →  調合実行  →  ターン終了で納品
     US-006              US-001            US-001          US-101         US-103
        ↓
  納品結果オーバーレイ表示  →  「続ける」  →  庭へ復帰  →  （次ターンへ）
        US-101                 US-102        US-102
```

### ジャーニー2: 工房への寄り道

```
庭 or 調合  →  ショップアイコン押下  →  工房強化画面  →  閉じる  →  元の画面へ復帰
  US-001            US-003                 US-003        US-003        US-003
```

### ジャーニー3: 昇格試験と終局

```
ターン終了 → ランク判定確定 → 昇格試験開始（調合画面・庭タブ無効）
 US-103        US-103              US-201
    ↓
 試験ターン進行 → 合否確定 ─┬─ SUCCESS(非最終ランク) → 工房強化画面        US-202
     US-201        US-201    ├─ SUCCESS(最終ランク)   → ResultScreen(CLEAR)  US-204
                             ├─ FAILURE(継続可)       → 庭画面               US-203
                             └─ FAILURE(規定回数降格) → ResultScreen(OVER)   US-205
```
