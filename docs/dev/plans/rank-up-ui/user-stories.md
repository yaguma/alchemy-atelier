## ペルソナ

### ペルソナ1: プレイヤー

- **役割**: 「Atelier」をプレイする個人開発者本人（テストプレイヤー）
- **目的**: 昇格試験（ランクノルマを制限ターン内に達成する一発勝負の局面）を、通常の調合画面の延長として迷わずプレイしたい
- **技術レベル**: 中級（自らゲームを開発しているため仕様理解は深いが、UI上の体験としては一般プレイヤーと同じ視点で評価する）

### ペルソナ2: 開発者（実装者・レビュアー）

- **役割**: 本Planを実装・レビューするGDScript開発者
- **目的**: 既存`AlchemyScreen`の標準パターン（シグナル自己購読・`_exit_tree()`解除・`ERROR_MESSAGES`辞書パターン）を崩さずに試験モード対応を追加し、GdUnit4で回帰テスト可能な状態にしたい
- **技術レベル**: 上級（Godot/GDScript、Feature-Based Architecture、Functional Core/Imperative Shellの原則に精通）

## エピック1: 試験中の調合〜納品フロー

### US-001: 調合するたびに自動で納品される 🔵

**私は** プレイヤー **として**
**昇格試験中に調合を実行したら、自動的に結果が納品されて試験ノルマに反映されてほしい**
**そうすることで** 通常モードのように毎回「終了ターン」を押す手間なく、テンポよく試験を進められる

- **関連要件**: FR-101
- **優先度**: Must Have
- **受入基準**: AC-005

### US-002: 試験中は「終了ターン」ボタンを操作しない 🔵

**私は** プレイヤー **として**
**昇格試験中は「終了ターン」ボタンが表示されず、誤って手動納品を試みることがないようにしたい**
**そうすることで** 試験中の操作手順（調合実行またはターンを進める、の2択のみ）に迷わない

- **関連要件**: FR-203, FR-204, FR-407
- **優先度**: Must Have
- **受入基準**: AC-004

## エピック2: 残りターンの可視化

### US-101: 試験の残りターン数を確認できる 🟡

**私は** プレイヤー **として**
**昇格試験中、あと何ターンで試験が終わるのかを画面上で確認したい**
**そうすることで** 残りターン数を踏まえて素材投入の戦略（品質重視か安全策か）を判断できる

- **関連要件**: FR-004, FR-106, FR-201, FR-202
- **優先度**: Must Have
- **受入基準**: AC-002

### US-102: 残りターン算出ロジックのテスト容易性 🟡

**私は** 開発者 **として**
**残りターン数の算出ロジックを`static func`として切り出し、GdUnit4から単体で境界値テストできるようにしたい**
**そうすることで** 表示バグ（残りターン数のマイナス表示等）を早期に検出できる

- **関連要件**: FR-302
- **優先度**: Should Have
- **受入基準**: AC-002

---

## エピック3: デッドロックの回避

### US-201: 素材がなくてもターンを進められる 🔵

**私は** プレイヤー **として**
**投入できる素材がない、または解禁レシピがない状況でも、「ターンを進める」ボタンで試験を進行させたい**
**そうすることで** 詰み（デッドロック）状態に陥らず、試験の結果（成功/失敗）を必ず迎えられる

- **関連要件**: FR-005, FR-102, FR-201, FR-202, FR-406
- **優先度**: Must Have
- **受入基準**: AC-003

---

## エピック4: 試験開始・終了のフィードバック

### US-301: 試験開始をメッセージで知る 🟡

**私は** プレイヤー **として**
**昇格試験が始まったとき、画面の表示が試験モードに切り替わったこととメッセージで気づきたい**
**そうすることで** 通常の調合と試験中の調合を混同せず、緊張感を持って臨める

- **関連要件**: FR-002, FR-003, FR-103
- **優先度**: Should Have
- **受入基準**: AC-006

### US-302: 試験の成功/失敗結果をメッセージで知る 🟡

**私は** プレイヤー **として**
**昇格試験の結果（成功/失敗）が確定したとき、演出はなくてもよいのでテキストで結果を知りたい**
**そうすることで** 試験が終わったことと、その結末を確実に認識できる

- **関連要件**: FR-104
- **優先度**: Must Have
- **受入基準**: AC-007

### US-303: 試験継続中に余計な通知を受けない 🟡

**私は** プレイヤー **として**
**試験がまだ継続中である場合（結果確定シグナルが`CONTINUE`を返した場合）には、結果メッセージのような紛らわしい通知を出さないでほしい**
**そうすることで** 「試験が終わった」という誤解を生まない

- **関連要件**: FR-105
- **優先度**: Should Have
- **受入基準**: AC-008

## エピック5: 案内メッセージ（在庫切れ対応）

### US-401: 詰みかけた時に案内メッセージを見る 🟡

**私は** プレイヤー **として**
**在庫が空、または解禁レシピが選択できない状況になったとき、「ターンを進める」で切り抜けられることを案内するメッセージを見たい**
**そうすることで** 何をすればよいか分からず操作に迷う時間をなくせる

- **関連要件**: FR-205, FR-206, FR-301
- **優先度**: Should Have
- **受入基準**: AC-010

## エピック7: 実装の一貫性・保守性（開発者視点）

### US-601: 新規シーンを作らず既存AlchemyScreenを拡張する 🔵

**私は** 開発者 **として**
**新規`Control`シーンを作成せず、既存`AlchemyScreen`に試験モード分岐を追加する形で実装したい**
**そうすることで** レシピ選択・投入枠・在庫一覧・プレビューといった既存UIロジックを二重実装せずに済む

- **関連要件**: FR-001
- **優先度**: Must Have
- **受入基準**: AC-001

### US-602: 既存Feature間参照の先例を踏襲する 🟡

**私は** 開発者 **として**
**`features/alchemy/ui`から`features/guild/ui`（`GuildDeliveryScreen`）を直接参照する既存の統合済み構造を、本Planでも崩さず踏襲したい**
**そうすることで** アーキテクチャルール上の逸脱を新たに増やさず、既存の実運用上の先例内に留める

- **関連要件**: CON-001, FR-408
- **優先度**: Must Have
- **受入基準**: AC-001, AC-011

### US-603: 試験の実プレイ発火経路の欠落を明確化する 🔵

**私は** 開発者 **として**
**`GameState.commit_rank_outcome()`/`commit_exam_outcome()`が現状プロダクションコードのどこからも呼ばれておらず、実プレイでは`exam_started`/`exam_outcome_confirmed`が発火しないという設計ギャップを、要件文書上で明示的に認識しておきたい**
**そうすることで** 本Planの受入基準が「統合テストでは検証できるが実プレイでは未発火」という限定的な状態であることを、後続Plan/Issueの判断者が正しく理解できる

- **関連要件**: CON-005
- **優先度**: Won't Have（ユーザー確認済み。配線トリガーの実装は本Planに含めず別Plan/別Issueとする）
- **受入基準**: AC-009

## ユーザージャーニー

### ジャーニー1: 試験開始から成功までの経路

```
制限ターン到達+ランクノルマ0（既存rank Plan） → exam_started発行 → AlchemyScreenが試験モード表示に切替
                                                    US-301(FR-103)         US-301(FR-002/201/202)
      → 調合実行のたび自動納品・ターン消費 → 残りターン表示を確認しつつ調合を継続 → ノルマ0到達でexam_outcome_confirmed(SUCCESS)
          US-001(FR-101)                        US-101(FR-004/106)              US-302(FR-104)
      → AlchemyScreenが通常モード表示へ復帰（工房強化画面遷移は別Plan、US-502）
```

### ジャーニー2: 素材切れからターンを進めて試験終了に至る経路

```
在庫・解禁レシピが尽きる → 案内メッセージ表示 → 「ターンを進める」を押下 → advance_exam_turn()でターン消費
    US-401(FR-205)            US-401(FR-206)          US-201(FR-005/102)         US-201(FR-102)
  → 制限ターン到達でexam_outcome_confirmed(SUCCESS/FAILURE) → AlchemyScreenが結果メッセージを表示
                        US-302(FR-104)                              US-302(FR-104)
```
