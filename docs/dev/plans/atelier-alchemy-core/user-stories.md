## ペルソナ

### ペルソナ1: 未来の開発者（自分自身 / Claude Code）

- **役割**: 本プロジェクト「Atelier」の個人開発者（ゲームデザイナー兼プログラマー）本人、および今後のセッションでコードを書くClaude Code
- **目的**: Phase 1で整備された基盤（ディレクトリ構造・GameState/RngService・日本語フォント・起動フロー・品質チェックコマンド）の上に、庭/調合/ギルド納品/工房強化/ランク進行の各Featureを迷いなく実装したい
- **技術レベル**: 上級（Godot/GDScriptの設計ルールを`.claude/rules/`に自ら定義している）。ただしGodotプロジェクトの新規スキャフォールディング作業自体は本Planで初めて行う

## エピック1: プロジェクトスキャフォールディング

### US-001: ディレクトリ構造が最初から用意されている 🔵

**私は** 未来の開発者 **として**
**`atelier/`にFeature-Based Architectureのディレクトリツリーが最初から用意されている状態**をしたい
**そうすることで** 各Feature実装時にディレクトリ構成で迷わず、`architecture.md`の設計案通りにファイルを配置できる

- **関連要件**: FR-001, FR-002, FR-003
- **優先度**: Must Have
- **受入基準**: AC-001, AC-002

---

## エピック2: 状態管理基盤

### US-002: GameStateの最小骨組みが実装されている 🔵

**私は** 未来の開発者 **として**
**`GameState` Autoloadが`current_phase`/`gold`/`current_turn`と`phase_changed` signal、`get_state()`（ディープコピー返却）を最小実装済みである状態**をしたい
**そうすることで** 各Feature実装時に「フィールドを外部から直接書き換えない」「`get_state()`の戻り値は安全に読み取れる」という状態管理ルールに最初から従える

- **関連要件**: FR-004, FR-005, FR-103, FR-406
- **優先度**: Must Have
- **受入基準**: AC-003, AC-004

### US-003: RngServiceの最小骨組みが実装されている 🔵

**私は** 未来の開発者 **として**
**`RngService` Autoloadが`set_seed()`/`randf()`等の最小APIを持ち、同一seedで同一の乱数列を再現できる状態**をしたい
**そうすることで** Domain層の純粋関数が乱数を引数で受け取る設計（Functional Core原則）を、各Feature実装時にそのまま利用できる

- **関連要件**: FR-006, FR-105
- **優先度**: Must Have
- **受入基準**: AC-006

### US-008: GameState/RngServiceの基本GUTテストがある 🔵

**私は** 未来の開発者 **として**
**`get_state()`のディープコピー検証・`reset_for_test()`の初期化検証・`RngService.set_seed()`の再現性検証がGUTテストとして存在する状態**をしたい
**そうすることで** 今後GameState/RngServiceを拡張する際に、既存の骨組みを壊していないことを自動テストで確認できる

- **関連要件**: FR-104, FR-107
- **優先度**: Should Have
- **受入基準**: AC-005, AC-011

### US-012: reset_for_test()がリリースビルドで誤って実行されない 🟡

**私は** 未来の開発者 **として**
**`reset_for_test()`がデバッグビルドでのみ実行され、リリースビルドではガードにより防止される状態**をしたい
**そうすることで** テスト専用APIが誤って本番実行パスに紛れ込むことを防げる

- **関連要件**: FR-201
- **優先度**: Must Have
- **受入基準**: AC-005

---

## エピック3: 日本語フォント対応

### US-004: 日本語テキストが正しく表示される 🔵

**私は** 未来の開発者 **として**
**`UiTheme`にCJK対応フォント定数が定義され、プロジェクト共通`Theme`リソースに適用されている状態**をしたい
**そうすることで** 各Feature画面を実装する際に日本語テキストが矩形/豆腐文字にならず、個別に対応する手間がかからない

- **関連要件**: FR-007, FR-008
- **優先度**: Must Have
- **受入基準**: AC-007

### US-011: BootSceneで日本語フォント動作を目視確認できる 🟡

**私は** 未来の開発者 **として**
**BootScene上に日本語の仮ラベルが表示され、目視確認の手順が文書化されている状態**をしたい
**そうすることで** フォント設定変更時に毎回同じ手順で素早く動作確認できる

- **関連要件**: FR-301
- **優先度**: Could Have
- **受入基準**: AC-015

## エピック4: 起動フロー

### US-005: BootScene→MainScene遷移が動作する 🔵

**私は** 未来の開発者 **として**
**起動時に`BootScene`がフォント適用とマスターデータ検証配線を行い、空の`MainScene`へ自動的に遷移する状態**をしたい
**そうすることで** 各Feature実装時に、起動シーケンスの土台を意識せず画面追加に集中できる

- **関連要件**: FR-101, FR-102
- **優先度**: Must Have
- **受入基準**: AC-008

### US-006: マスターデータ検証の配線だけが先に用意されている 🔵

**私は** 未来の開発者 **として**
**`MasterDataLoader.validate_references()`という関数シグネチャが存在し、`BootScene`から呼び出し配線されている状態（中身はスタブでよい）**をしたい
**そうすることで** 後日マスターデータ型（`MaterialMaster`等）を実装する際、検証ロジックの実装先とBootSceneからの呼び出し経路をゼロから設計し直さずに済む

- **関連要件**: FR-009
- **優先度**: Must Have
- **受入基準**: AC-009

---

## エピック5: テスト・Lint基盤

### US-007: GUT導入手順書が提示される 🔵

**私は** 未来の開発者 **として**
**GUTアドオンのAssetLib経由インストール手順書と、インストール後の動作確認コマンドが提示されている状態**をしたい
**そうすることで** 手動でしか行えないインストール作業を迷わず完了し、以降のGUTテスト実行に進める

- **関連要件**: FR-010
- **優先度**: Must Have
- **受入基準**: AC-014

### US-009: gdlint/gdformatが実行できる 🔵

**私は** 未来の開発者 **として**
**`gdlint`/`gdformat --check`が`atelier/features/`, `shared/`, `autoload/`に対してエラー・フォーマット崩れなく実行できる状態**をしたい
**そうすることで** コミット前チェック（`.claude/rules/implement-workflow.md`参照）を各Feature実装時からそのまま利用できる

- **関連要件**: FR-108, FR-109
- **優先度**: Must Have
- **受入基準**: AC-012, AC-013

### US-010: クリーンチェックアウト直後でもインポートが成功する 🔵

**私は** 未来の開発者 **として**
**`.godot/`インポートキャッシュが存在しない状態から`godot --headless --path atelier --import`が正常終了する状態**をしたい
**そうすることで** CI環境や新規クローン直後でも安定してテスト・Lintを実行できる

- **関連要件**: FR-106
- **優先度**: Must Have
- **受入基準**: AC-010

## エピック6: スコープガードレール

### US-013: 各Feature実装が本Planに混入していないことが確認できる 🔵

**私は** 未来の開発者 **として**
**本Planの成果物に庭/調合/ギルド納品/工房強化/ランク進行のFeatureロジック・マスターデータ実データ・UI画面・セーブロード機能・エクスポートビルド設定が含まれていないことをレビューで確認できる**をしたい
**そうすることで** Phase 1の基盤構築というスコープを厳密に保ち、後続の各Feature Planとの責務分担を崩さない

- **関連要件**: FR-401, FR-402, FR-403, FR-404, FR-405
- **優先度**: Must Have
- **受入基準**: AC-016
