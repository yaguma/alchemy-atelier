# Task: 手動プレイテスト手順書を作成する

## Goal

DebugPanel（task 001-003）を使って、庭→調合→ギルド納品→ランク進行（G〜S全ランク）→工房強化のループを人間が一通りプレイ確認するためのチェックリストを作成する。実装タスクではなくドキュメント作成タスクのため、implement-workflow.mdの「Directモード」に該当する（テスト不要）。

## Interfaces

該当なし（ドキュメント作成タスク）。

## Test Strategy

該当なし（GdUnit4テストは作成しない）。作成した手順書自体をユーザーが実際に一度なぞり、記載内容で迷わず最後まで到達できることを確認する（このタスクの完了条件）。

## Implementation Notes

- 参照すべき既存コード:
  - `.claude/rules/godot-debug-tools.md`（Godotエディタでの実行手順、リモートシーンツリーの使い方、スクリーンショット撮影手順）
  - `atelier/tests/integration/test_main_scene_full_loop_playthrough.gd`（自動テストが既にカバーしている観点＝重複確認を避けるため、手順書は「自動テストでは見えない部分」＝画面遷移の見た目・パフォーマンス・日本語表示崩れ・操作感に絞る）
  - CLAUDE.md「次のステップ」（本Planが対応する残作業の原文）
- 実装のヒント: チェックリストは以下の観点を含めること
  1. 起動〜タイトル〜スロット選択〜新規ゲーム開始までの導線
  2. 庭: 種植え付け→ターン終了→収穫までの一連操作と表示崩れの有無
  3. 調合: レシピ選択・素材投入・調合実行・ターン終了の一連操作
  4. ギルド納品: 納品結果画面の表示・「続ける」導線
  5. ランク進行: DebugPanelの「次ランクへ」でG→S全ランクを素早く辿り、各ランクでランク名・ノルマ表示・RankHudが正しく更新されるか
  6. 昇格試験: 通常フローで最低1回は試験開始→合否確定までを実際に操作して確認（DebugPanelでスキップしない。試験画面自体の検証が目的のため）
  7. 工房強化: DebugPanelの「G+1000」でゴールドを確保し、恒久強化・消耗投資それぞれの購入〜反映〜画面復帰
  8. セーブ/ロード・設定画面・一時停止メニューとの相互作用（プレイ中にポーズを挟んでも状態が壊れないか）
  9. 発見した不具合の記録欄（再現手順・スクリーンショット・severityの3項目を書けるテンプレート行を用意する。本Planでは修正しないため、別Plan起票用のメモ欄として使う）
- 注意事項: 本チェックリストは「実装計画のタスク」ではなく「これを使って人間が実際にプレイする」ためのドキュメントである。dev-implでコードを書くタスクではないため、dev-implスキルの対象外として扱ってよい（ユーザーまたはClaude Codeが直接Writeツールで作成する）。
