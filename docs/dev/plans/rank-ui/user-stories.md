## ペルソナ

### ペルソナ1: プレイヤー

- **役割**: 「Atelier」をプレイする個人開発者本人（テストプレイヤー）
- **目的**: ギルドランクを昇りSランクの昇格試験に成功してゲームをクリアする、または降格が重なりゲームオーバーになる一連の結末を明確に認識したい
- **技術レベル**: 中級（自らゲームを開発しているため仕様理解は深いが、UI上の体験としては一般プレイヤーと同じ視点で評価する）

### ペルソナ2: 開発者（実装者・レビュアー）

- **役割**: 本Planを実装・レビューするGDScript開発者
- **目的**: 既存の`PhaseIndicator`/`GoldDisplay`/`AlchemyScreen`と一貫した標準パターンでResultScreenを実装し、GdUnit4で回帰テスト可能な状態にしたい
- **技術レベル**: 上級（Godot/GDScript、Feature-Based Architecture、Functional Core/Imperative Shellの原則に精通）

## エピック1: ゲーム終了結果の表示

### US-001: Sランク昇格試験成功時のクリア表示 🔵

**私は** プレイヤー **として**
**Sランク（最終ランク）の昇格試験に成功したとき、「ゲームクリア」に相当するメッセージを見たい**
**そうすることで** 自分がゲームの最終目標を達成したことを実感できる

- **関連要件**: FR-002, FR-004, FR-101, FR-102, FR-302, FR-401
- **優先度**: Must Have
- **受入基準**: AC-001, AC-005

### US-002: ゲームオーバー時のオーバー表示 🔵

**私は** プレイヤー **として**
**降格が繰り返される等でゲームオーバー条件が成立したとき、「ゲームオーバー」に相当するメッセージを見たい**
**そうすることで** ゲームの終了を明確に認識できる

- **関連要件**: FR-002, FR-103, FR-401
- **優先度**: Must Have
- **受入基準**: AC-002, AC-005

### US-003: 標準的なシグナル自己購読パターンでの実装 🔵

**私は** 開発者 **として**
**ResultScreenが`GameState.game_over`/`game_cleared`を自身の`_ready()`で購読し、`_exit_tree()`で確実に購読解除する標準パターンで実装されていてほしい**
**そうすることで** 既存の`PhaseIndicator`/`GoldDisplay`と一貫した、保守しやすく購読リーク（メモリリーク）のないコードになる

- **関連要件**: FR-001, FR-104, FR-301
- **優先度**: Must Have
- **受入基準**: AC-003

## エピック2: ゲームクリア判定ロジックの正確性

### US-004: 真のゲームクリアとエラーケースの区別 🔵

**私は** 開発者 **として**
**次ランクのRankMaster欠落というマスターデータ不整合エラーの分岐で、誤って`game_cleared`が発行されないようにしたい**
**そうすることで** 真のゲームクリアとデータ不整合エラーが混同されず、ResultScreenが誤った「クリア」表示をしてしまう不具合を防げる

- **関連要件**: FR-201, FR-405
- **優先度**: Must Have
- **受入基準**: AC-004

### US-005: 最小限の表示内容 🟡

**私は** プレイヤー **として**
**結果画面では到達ランクや降格回数等の詳細な統計情報ではなく、結果種別を示すシンプルなメッセージだけを見たい**
**そうすることで** ゲームの結末を一目でシンプルに把握できる

- **関連要件**: FR-003, FR-404
- **優先度**: Should Have
- **受入基準**: AC-008

---

## エピック3: スコープ外境界の明示（Won't Have）

### US-006: 次へ進むボタン（本Planでは対象外） 🔵

**私は** プレイヤー **として**
**（将来的には）結果画面から次の操作（タイトルへ戻る等）に進むボタンを使いたい**
**そうすることで** ゲーム終了後の操作に迷わない

- **関連要件**: FR-402
- **優先度**: Won't Have（タイトル画面・セーブロード機能が設計スコープ外のため、本Planはボタンなしの表示専用画面とする）
- **受入基準**: AC-006

### US-007: MainSceneへの統合（本Planでは対象外） 🔵

**私は** 開発者 **として**
**（将来的には）ResultScreenを`MainScene`に組み込み`current_phase`に応じて表示切替したい**
**そうすることで** 実際のゲームプレイフローの中で結果画面が機能する

- **関連要件**: FR-403
- **優先度**: Won't Have（guild-ui・alchemy-ui Planと同様、MainScene統合は別Task/別Planで扱う）
- **受入基準**: AC-007
