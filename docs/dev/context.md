## Coding Conventions

### Naming（`.claude/rules/coding-style.md`準拠、`.gdlintrc`で機械強制）

| Target | Convention | Example |
|--------|-----------|---------|
| 変数・関数 | snake_case | `material_list`, `calculate_reward` |
| クラス（`class_name`） | PascalCase | `QualityCalculator`, `WorkshopScreen` |
| シグナル | snake_case | `phase_changed`, `screen_closed` |
| 定数 | UPPER_SNAKE_CASE | `GARDEN_SLOT_COUNT`, `QUALITY_SCORE_MIN` |
| ファイル | snake_case | `quality_calculator.gd`, `workshop_screen.gd` |
| privateメンバ | 先頭`_` | `_active_tab`, `_filter_and_sort()` |
| テストファイル | `test_{対象}.gd`、`extends GdUnitTestSuite` | `test_quality_calculator.gd` |

### ファイル冒頭の記述順序（`.gdlintrc: class-definitions-order`で強制）

`tools → classnames → extends → docstrings → signals → enums → consts → staticvars → exports → pubvars → prvvars → onreadypubvars → onreadyprvvars → others`

### Error Handling

- 明示的な戻り値型`Result`（`shared/entities/result.gd`、success/error_code）でDomain層の失敗を表現（例外を投げない）
- UI層は`Result.success`を見て早期return + トースト表示（`workshop_screen.gd`の`_on_purchase_requested()`参照）

### Static Typing（🔵 `.claude/rules/coding-style.md`で必須、実コードでも徹底）

- 全変数・引数・戻り値に型注釈（`var x: int`, `func foo(a: int) -> bool`）
- `Variant`型は型ガードなしで使用禁止
- 配列は`Array[MaterialInstance]`のように要素型を明示

### Comments

- 信号機コメント（🔵確定仕様 / 🟡推測・暫定 / 🔴AI補完・未確定）が設計文書からコードまで一貫して使われている（`quality_calculator.gd`, `game_balance.gd`, `workshop_screen.gd`等で多数確認）
- 「なぜ」を説明する目的コメントが中心（要件書の節番号やタスク番号を対応付ける形式が多い）

### Logging

- `push_warning()` / `push_error()`のみ（本番`print()`禁止、`.claude/rules/performance.md`）
