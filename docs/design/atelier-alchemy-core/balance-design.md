# バランス設計

作成日: 2026-08-04
準拠要件: [`../../spec/atelier-alchemy-core/requirements.md`](../../spec/atelier-alchemy-core/requirements.md)（以下「要件定義書」）§5「数値設計（仮置き）」・§7「未確定事項」

> ⚠️ 本文書に記載する数値は原則として要件定義書§5の仮値をそのまま引き継いだ**プレースホルダー**である。具体的な確定値は`CLAUDE.md`の「次のステップ」に記載の通り、別途バランス調整フェーズ（本プロジェクトには`.claude/skills/balance-tuning-cycle/`スキルが存在する）で決定する。本文書の役割は「どこにTBD値が存在するか」「どういう方針で調整すべきか」を明文化することであり、数値そのものの確定ではない。

## 設計方針

- コンセプト文書§4「体験の強弱カーブ」に定義された緊張感カーブ（Gランクは学習、S ランクは最大緊張）を、ランクHP・制限ターン数・敵の要求品質の傾斜で実現する
- 特性は「貢献度向き／報酬向き」の真のトレードオフである必要があるため、両者の基礎倍率は同水準に揃え、一方が常に優位にならないようにする（コンセプト文書§7「v7.0 主要変更点」の「真のジレンマ」参照。🔵2026-08-05修正: 旧版は誤って「要件定義書L294」からの引用としていたが、要件定義書は230行程度でL294は存在しない。実体はコンセプト文書側の記述であり、PRレビューNaming/Logic各観点で指摘された行番号誤引用の一例として修正した）
- 金でターン制限を延長する手段は意図的に存在しない（要件定義書§4「ショップ／工房強化」参照）。この制約は数値バランスでも崩さない（例えばショップ価格をどれだけ下げても実質的にターン延長と等価になる効果を持たせない）。ただし**ランクHPが制限ターンより先に0になった場合の残りターンは、意図的な早期クリアボーナス（報酬稼ぎ期間）として許容する**（要件定義書§2「勝敗条件」参照。これはターン制限の延長ではなく、早めに切り上げたランクの余剰時間を使う設計）

🔵 コンセプト文書§4・§5の記述に基づく。

## 難易度曲線

```
難易度
  ↑
  │                              ╭──（S: 最終試験）
  │                        ╭────╯
  │                  ╭────╯（B-A: 高効率調合が必須）
  │            ╭─────╯
  │      ╭─────╯（D-C: 品質/特性の食い合いが厳しくなる）
  │╭─────╯（G-F-E: 基本ループ習得→特性解禁）
  └──────────────────────────────────────→ 進行度
      G    F    E    D   C-B   A-S
```

🔵 コンセプト文書§4「1プレイ全体（60〜90分）」の表をそのままグラフ化。

### G-Fランク（序盤: 00:00-25:00相当）

- 目標: 植える→収穫→調合の基本ループを学ぶ
- 難易度: 低
- 重点: **特性は封印**（要件定義書§6「Gランク・1ターン目」）。品質のみを意識させ「混ぜたら作れた」の気持ちよさを優先する
- 数値方針: ランクHP・制限ターン数はクリア失敗がほぼ起きない水準に設定する（🟡具体値TBD）

### Eランク（前半: 25:00-40:00相当）

- 目標: 特性（貢献度向き／報酬向き）の解禁と二分の理解
- 難易度: 中
- 重点: 「今ランクを削る品を作るか、稼いで強化する品を作るか」の先行投資が初めて意味を持つ

### D-Cランク（中盤: 40:00-55:00相当）

- 目標: 品質 vs 特性の食い合いを最適化し、指定調合物に対応する
- 難易度: 中〜重
- 重点: 制限ターンのプレッシャーが強まり始める（🟡ランクごとの制限ターン傾斜値はTBD）

### B-A-Sランク（終盤: 55:00-90:00相当）

- 目標: 限られた在庫と枠でのトレードオフを詰め、最終試験に備える
- 難易度: 最大
- 重点: 高効率な調合設計が必須。Sランクは昇格試験（庭なし・専用試験HP・超短期ターンで通常の調合/納品ループを流用する設計。🔵確定、数値は🟡TBD。[`game-mechanics.md`](./game-mechanics.md) 参照）を突破すればゲームクリア

🔵 各ランク帯の目標・重点は要件定義書§6の想定プレイフロー、コンセプト文書§4の表に忠実。ランクごとの具体的なHP・制限ターン数値は次節の通り未確定。

## 調整ガイドライン

### 調整の優先順位

1. **品質倍率・基礎貢献度/基礎報酬**（すべての価値計算の土台。これが決まらないと他のTBDの試算ができない）
2. **ランク制限ターン数の傾斜**（緊張感カーブに直結）
3. **庭関連の数値**（成熟ターン数・枯死猶予ターン数・庭スロット数。庭は供給層のため調合ほどシビアな調整は不要だが、供給が枯渇/過剰にならない範囲に収める）
4. **ショップ価格・降格許容回数**（プレイヤーの詰み判定に関わるため、他数値が固まった後に最終調整する）

🟡 優先順位は本文書での提案。基礎貢献度/報酬を最優先とする理由は、他の全ての倍率（品質倍率・特性ボーナス・指定合致ボーナス）がこの値に掛け算される関係にあるため。

### 調整時の注意点

- 貢献度向き特性と報酬向き特性の基礎倍率は、意図的に非対称にする場合を除き同水準に保つこと（一方が支配戦略にならないようにする。コンセプト文書§7「v7.0 主要変更点」の「真のジレンマ」を守るため）
- 「品質を4枠とも高品質・無特性で埋める」戦略と「2枠特性+2枠高品質」戦略の期待値差が大きすぎないよう検証する（要件定義書§6のEランク以降プレイフロー例が示す択一が実際に機能するか）
- 金でターン制限を実質的に延長できてしまう抜け道（例: 触媒で品質を大幅に底上げして少ないターンで大量に稼げる等）がないか、数値確定のたびに確認する。ただしランクHP早期到達後の残りターンでの報酬稼ぎは、意図的な早期クリアボーナスとして許容済みの仕様である（本節冒頭「設計方針」参照。抜け道ではない）
- 昇格試験HPの難度係数は、通常ランク終盤の1〜2手分の貢献度で十分削り切れる水準に収めること。係数が高すぎると「事前準備が全てで試験自体に意味がない」または「理不尽な即死」になり、低すぎると「昇格の壁」としての緊張感（コンセプト文書§4「Sランク: 最終試験、降格リスクあり」）が失われる（🟡本文書での注意喚起。具体的な検証はプロトタイプ/バランス調整フェーズで行う）
