# 入力システム設計

作成日: 2026-08-04
準拠要件: [`../../../spec/atelier-alchemy-core/requirements.md`](../../../spec/atelier-alchemy-core/requirements.md)

> ⚠️ 要件定義書・コンセプト文書のいずれにも対応入力デバイス・キーバインドの明示規定はない。コンセプト文書§2「操作密度: 落ち着いて考える（ターン制）」から、リアルタイム性の高い入力は不要と推測できる程度である。本文書の内容は🟡🔴本文書での提案が大半を占める。

## 対応入力デバイス

| デバイス | 対応状況 | 備考 |
|----------|----------|------|
| キーボード + マウス | 必須 | プラットフォームはPC（要件定義書§概要「プラットフォーム: PC」🔵） |
| ゲームパッド | 🔴未定 | 要件定義書に規定なし。ターン制・カード選択中心のUIのため優先度は低いと推測（🔴） |
| タッチスクリーン | 🔴対象外と推測 | PC想定のため（🔴要件定義書に明記なし） |

## キーバインド設定（暫定案）

本ゲームは基本的にマウス操作（クリック/ドラッグ）を主とする想定。ドラッグ&ドロップで在庫→投入枠へ素材を配置する操作（[alchemy.md](./screens/alchemy.md)参照）が中心となるため、キーボードは補助的な位置づけとする。

### デフォルトキーバインド（暫定・🔴要検証）

| アクション | キーボード | 備考 |
|-----------|-----------|------|
| 決定（購入・投入確定等） | Enter / Space | Godot標準の`ui_accept`を流用 |
| キャンセル（画面を閉じる） | Escape | Godot標準の`ui_cancel`を流用 |
| タブ切替（庭⇔調合） | Tab | 🔴本文書での提案。要検証 |
| 調合を実行する | 🔴未定 | ショートカット不要の可能性（誤操作防止のため意図的にマウスのみにする案もある） |

### カスタマイズ可能なアクション

🔴要件定義書に規定なし。キーコンフィグ機能自体が必要かどうかも未確定（セーブ/ロード・設定画面が設計スコープ外であることから、キーコンフィグ機能も現バージョンではスコープ外と推測🟡）。

## 入力の優先度

1. **UI入力**（ダイアログ表示中はダイアログが最優先）
2. **画面入力**（庭/調合/ショップ等、通常のゲーム操作）

🟡 本ゲームにはリアルタイム性のあるシステム入力（ポーズ等）は現バージョンのスコープに存在しないため、一般的な3段階優先度モデルから「システム入力」層を省略した。

## 同時入力の処理

本ゲームはターン制・カード選択中心のUIであり、同時入力（反対方向の同時押し等）が問題になる場面は想定されない（🔵コンセプト文書§2「操作密度: 落ち着いて考える」より）。

## 入力バッファ

不要（🔵ターン制ゲームであり、アクションゲームのような先行入力受付の必要性がないため）。
