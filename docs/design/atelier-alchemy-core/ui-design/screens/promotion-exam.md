# 昇格試験画面 詳細設計

作成日: 2026-08-04
準拠要件: [`../../../../spec/atelier-alchemy-core/requirements.md`](../../../../spec/atelier-alchemy-core/requirements.md) §2「勝敗条件」・§3「昇格試験」・§4「昇格試験（Exam）」

> 🔵2026-08-04のヒアリングにより、昇格試験は「通常ターンループの調合・納品をそのまま流用した、庭なし・専用HP・超短期ターンの一発勝負」として確定した。そのため本画面は[`alchemy.md`](./alchemy.md)・[`guild-delivery.md`](./guild-delivery.md)の**UI要素をほぼそのまま再利用**し、庭タブと試験HPバーの有無だけが通常画面と異なる。

## 基本情報

| 項目 | 値 |
|------|-----|
| 画面ID | SCR-005 |
| 親画面 | 庭画面/調合画面（制限ターン到達かつランクHP0で自動遷移） |
| 子画面 | 工房強化・ショップ画面（成功時）、庭画面（失敗時、同ランク再挑戦） |

```
┌─────────────────────────────────────────────┐
│  {ランク名}昇格試験        試験HPバー  残り{n}ターン │ ← 通常のRankHudを試験モードに切替表示
├─────────────────────────────────────────────┤
│ レシピ: [▼ {選択中のレシピ名}]                 │ ← alchemy.mdと同一UI
├─────────────────────────────────────────────┤
│  投入枠1  投入枠2  投入枠3  投入枠4             │ ← alchemy.mdと同一UI
├─────────────────────────────────────────────┤
│ プレビュー: 品質{score} 発現特性[聖][金]        │
│            見込み貢献度{x} / 見込み報酬{y}      │
│            （※指定合致ボーナスのみ試験中は不適用）│
├─────────────────────────────────────────────┤
│  在庫一覧（投入元。※庭タブ自体が存在しない）    │
│  [薬草A][薬草B][鉱石S(聖)][鉱石A(聖)]...       │
│  （在庫0または解禁レシピ0の場合: 案内メッセージ）│
├─────────────────────────────────────────────┤
│      [調合を実行する]    [ターンを進める]       │
└─────────────────────────────────────────────┘
```

🔵 [`alchemy.md`](./alchemy.md) のワイヤーフレームから「[庭][調合]タブ」を除去し、`bar-rank-hp`を試験HP表示に差し替えたもの。調合実行後は[`guild-delivery.md`](./guild-delivery.md)と同じ結果表示（試験HP減少演出）を挟む。

🔴 **2026-08-05修正（PRレビューCritical#10対応）**: 旧版は「調合を実行する」以外にターンを進める手段がなく、在庫0または解禁レシピ0の状態で試験に入るとデッドロックした。「ターンを進める」ボタンを常設し、報酬・指定合致ボーナスの表示も[`alchemy.md`](./alchemy.md)と同じ形式（報酬は表示し、指定合致ボーナスのみ試験中は不適用）に修正した（🔵2026-08-05ヒアリングで試験中も報酬は通常どおり獲得すると確定）。

## 状態遷移

### 試験開始状態

制限ターン到達かつランクHP0で本画面へ自動遷移し、`PromotionExamResolver.start_exam`が生成した`ExamState`で`bar-exam-hp`・`txt-exam-turn`を初期化する（🔵[`core-systems.md`](../core-systems.md)、[`dataflow.md`](../dataflow.md)「昇格試験のデータフロー」参照）。

### 試験進行中状態

[`alchemy.md`](./alchemy.md)の「投入中状態」「実行可能状態」と同一。調合を実行するたびに[`guild-delivery.md`](./guild-delivery.md)相当の簡易結果表示（試験HP減少演出・報酬獲得表示）を挟み、`exam_elapsed_turn`が+1される。`btn-advance-turn`を押した場合は結果表示なしで即座にターンだけ進む（🔵2026-08-05修正、PRレビュー対応。ターン経過のトリガーは「調合実行」または「ターンを進めるボタン」の2通りに確定した）。

### 成功状態

`ExamOutcome.SUCCESS`（試験HP0到達）で、工房強化・ショップ画面（[workshop-shop.md](./workshop-shop.md)）へ遷移し、恒久投資を選択できる（購入は任意）。現在ランクがSだった場合は工房強化画面を経由せず、直接ゲームクリア画面へ遷移する（要件定義書§2「勝敗条件」、[`dataflow.md`](../dataflow.md) 参照）。降格回数カウンタは0にリセットされる。

### 失敗状態

`ExamOutcome.FAILURE`（制限ターン到達時に試験HP>0）で、庭画面へ戻り、同ランクに留まって再挑戦する（「降格」）。ランクHP・残りターンはリセットされ、庭・在庫・ゴールド・恒久投資は維持される（要件定義書§2「降格時のリセット規定」参照）。降格回数カウンタが規定回数（🟡TBD、仮3回）に達している場合はゲームオーバー画面へ遷移する。

## エラー状態（🔴2026-08-05追加、PRレビューCritical#10/Warning対応）

- **在庫が空、または解禁レシピが選択できない場合**: 在庫一覧に案内メッセージを表示し（🟡TBD文言）、`btn-execute`は無効化されるが`btn-advance-turn`は常に有効なため試験を進行させられる
- **試験制限ターン到達（ゲームオーバー分岐含む）**: 上記「失敗状態」参照

## イベント

| イベント名 | トリガー | 処理内容 |
|-----------|----------|----------|
| OnExamStarted | 制限ターン到達+ランクHP0 | `PromotionExamResolver.start_exam`で`ExamState`生成、本画面へ遷移 |
| OnExamAlchemyExecuted | 「調合を実行する」押下 | [`dataflow.md`](../dataflow.md)「昇格試験のデータフロー」参照。`daily_order`にnullを渡す点のみ通常と異なる。報酬は通常どおり獲得する |
| OnExamTurnAdvanced | 「ターンを進める」押下 | `PromotionExamResolver.advance_turn`を呼び`exam_elapsed_turn`のみ+1する（🔴2026-08-05追加） |
| OnExamResolved | `PromotionExamResolver.resolve_outcome`が`SUCCESS`/`FAILURE`を返した時 | 成功時: 降格回数カウンタを0にリセットし工房強化画面（Sランクなら直接ゲームクリア画面）へ。失敗時: `RankHpResolver.reset_for_retry`でランク状態をリセットし降格回数カウンタ+1、庭画面へ |
