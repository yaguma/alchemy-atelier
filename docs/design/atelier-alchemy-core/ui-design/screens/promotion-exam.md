# 昇格試験画面 詳細設計

作成日: 2026-08-04
準拠要件: [`../../../../spec/atelier-alchemy-core/requirements.md`](../../../../spec/atelier-alchemy-core/requirements.md) §2「勝敗条件」・§3「昇格試験」・§4「昇格試験（Exam）」

> 🔵2026-08-04のヒアリングにより、昇格試験は「通常ターンループの調合・納品をそのまま流用した、庭なし・専用HP・超短期ターンの一発勝負」として確定した。そのため本画面は[`alchemy.md`](./alchemy.md)・[`guild-delivery.md`](./guild-delivery.md)の**UI要素をほぼそのまま再利用**し、庭タブと試験HPバーの有無だけが通常画面と異なる。

## 基本情報

| 項目 | 値 |
|------|-----|
| 画面ID | SCR-005 |
| 親画面 | 庭画面/調合画面（制限ターン到達かつランクHP0で自動遷移） |
| 子画面 | 工房強化・ショップ画面（成功時）、庭画面（失敗時、同ランク再挑戦） |

```
├─────────────────────────────────────────────┤

├─────────────────────────────────────────────┤

```

🔵 [`alchemy.md`](./alchemy.md) のワイヤーフレームから「[庭][調合]タブ」を除去し、`bar-rank-hp`を試験HP表示に差し替えたもの。調合実行後は[`guild-delivery.md`](./guild-delivery.md)と同じ結果表示（試験HP減少演出）を挟む。

## 状態遷移

### 試験開始状態

制限ターン到達かつランクHP0で本画面へ自動遷移し、`PromotionExamResolver.start_exam`が生成した`ExamState`で`bar-exam-hp`・`txt-exam-turn`を初期化する（🔵[`core-systems.md`](../core-systems.md)、[`dataflow.md`](../dataflow.md)「昇格試験のデータフロー」参照）。

### 試験進行中状態

[`alchemy.md`](./alchemy.md)の「投入中状態」「実行可能状態」と同一。調合を実行するたびに[`guild-delivery.md`](./guild-delivery.md)相当の簡易結果表示（試験HP減少演出のみ、報酬表示なし）を挟み、`exam_elapsed_turn`が+1される（🟡ターン経過のトリガーは「1回の調合実行=1ターン」と本文書で仮定。[`game-mechanics.md`](../game-mechanics.md)「昇格試験について」参照。プロトタイプでの検証を推奨）。

### 成功状態

`ExamOutcome.SUCCESS`（試験HP0到達）で、工房強化・ショップ画面（[workshop-shop.md](./workshop-shop.md)）へ遷移し、恒久投資を選択できる（購入は任意）。現在ランクがSだった場合はゲームクリア画面へ遷移する（要件定義書L52）。

### 失敗状態

`ExamOutcome.FAILURE`（制限ターン到達時に試験HP>0）で、庭画面へ戻り、同ランクに留まって再挑戦する（「降格」）。降格回数カウンタが規定回数（🟡TBD、仮3回）に達している場合はゲームオーバー画面へ遷移する。

## イベント

| イベント名 | トリガー | 処理内容 |
|-----------|----------|----------|
| OnExamStarted | 制限ターン到達+ランクHP0 | `PromotionExamResolver.start_exam`で`ExamState`生成、本画面へ遷移 |
| OnExamAlchemyExecuted | 「調合を実行する」押下 | [`dataflow.md`](../dataflow.md)「昇格試験のデータフロー」参照。`daily_order`にnullを渡す点のみ通常と異なる |
| OnExamResolved | `PromotionExamResolver.resolve_outcome`が`SUCCESS`/`FAILURE`を返した時 | 成功/失敗に応じて工房強化画面 or 庭画面へ遷移、降格回数カウンタ更新 |
