# ギルド納品画面 詳細設計

作成日: 2026-08-04
準拠要件: [`../../../../spec/atelier-alchemy-core/requirements.md`](../../../../spec/atelier-alchemy-core/requirements.md) §3「ギルド納品」

## 基本情報

| 項目 | 値 |
|------|-----|
| 画面ID | SCR-003 |
| 親画面 | 調合画面（調合実行時に自動遷移/オーバーレイ表示） |
| 子画面 | なし（庭画面へ戻る） |

要件定義書L78「プレイヤー操作なし（自動決算）。結果の確認のみ」に基づき、**本画面にプレイヤーが能動的に操作するUI要素は存在しない**。演出を見せて自動的に（または「閉じる」押下で）庭画面へ戻る結果表示画面である。

## ワイヤーフレーム

```
┌─────────────────────────────────────────────┐
│              ギルド納品結果                   │
├─────────────────────────────────────────────┤
│  完成品: {調合物名}  品質{score}               │
│  発現特性: [聖][金]                            │
│  本日の指定調合物に  ✓合致（ボーナス+{n}%）    │
├─────────────────────────────────────────────┤
│  貢献度 +{contribution}  → ランクHPバー減少演出│
│  報酬   +{reward} G                            │
├─────────────────────────────────────────────┤
│                [閉じる/続ける]                 │
└─────────────────────────────────────────────┘
```

🟡 レイアウトは要件定義書§1「④フィードバック」（貢献度ダメージ演出、報酬獲得表示、指定合致ボーナス表示、ランクHPバーの変化）を画面として組み立てた本文書での提案。

## UI要素

| 要素ID | 種類 | 説明 | 状態 |
|--------|------|------|------|
| txt-product-name | テキスト | 完成した調合物名 | - |
| txt-quality | テキスト | 完成品の品質 | - |
| icon-trait-{tag} | アイコン | 発現した特性タグ一覧 | - |
| txt-order-match | テキスト | 本日の指定調合物への合致有無とボーナス率 | 合致/不合致 |
| bar-rank-hp | ランクHPバー | 減少アニメーションで貢献度反映を可視化 | - |
| txt-reward | テキスト | 獲得ゴールド | - |
| btn-continue | プライマリボタン | 結果を確認し庭画面へ戻る（一定時間後の自動遷移でも可、🟡TBD） | 常時有効 |

## 状態遷移

### 結果表示状態（単一状態）

本画面はプレイヤー操作を伴わないため、状態遷移は「表示→確認→閉じる」の一本道のみ。指定調合物に合致した場合のみ`txt-order-match`の表示がボーナス表示付きに変化する。

### ランククリア到達時の分岐（🟡本文書での提案）

このタイミングで`RankHpResolver.is_rank_cleared`が真になった場合、本画面の「続ける」操作後、次の画面遷移先が通常の庭画面ではなく「制限ターン到達待ち」または即座の昇格試験判定に分岐する可能性がある。具体的な分岐条件は要件定義書L126「制限ターン到達時にHPが0なら昇格試験」であり、**HP到達時点では即座に昇格試験へは移行しない**（制限ターンの到達が別条件として必要）。この解釈は[`dataflow.md`](../dataflow.md) の全体フロー図と一致する（🔵）。
